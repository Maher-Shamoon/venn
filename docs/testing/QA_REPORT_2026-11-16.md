## 2. Live checks (real Google account, built-in browser)

- Google sign-in returns `/app?code=…` (one-time code). No session token in the address. (Before: the token was in the address, so a copied link signed anyone in.)
- Google → setup → organization created → real dashboard; no "view as", no sample data.
- Sign out → Google again → straight to the dashboard of the organization.
- Strict Content-Security-Policy active: no violations; the sign-in shader and form work; Google sign-in works under it.
- API in Tokyo next to the database: shell call about 0.4 s (was about 1.6 s).
- Invitation delivery: Brevo's record shows invitations were delivered to Gmail (the message lands in Spam because the sender is a Gmail address relayed through Brevo).

## 3. Accessibility (axe-style rule engine, live pages)

Sampled 8 public pages and 8 app screens (via the sample workspace). Fixed: skip link without a target on every app screen, charts focusable inside an image role, invalid `role="text"` on animated numbers, empty pricing table header. Contrast warnings on About, Contact and Sign-up were the fade-in animation only (verified: after it settles, nothing is below 4.5:1).

Not covered: keyboard and screen-reader walkthroughs, zoom to 200%, real assistive technology (needs a person).

## 4. Reviews by specialist reviewers

**Security (no critical or high):** cross-organization isolation, role enforcement, self-approval prevention, SQL, uploads, secrets, CORS found sound. Fixed: CSP, HSTS, Permissions-Policy; OAuth state bound to its provider; JWT issuer required; API schema hidden in production.

**Code review:** fixed endless loader after a failed organization lookup (and the guard now times out to sign-in), retry-safe invitations in setup, single-submit in setup, stale invitation token cleanup, case-insensitive email comparison; weak tests strengthened.

**Performance:** fixed asset caching (one year, immutable); preload no longer fetches the whole app for signed-out visitors or slow connections.

## 5. Open items (not fixed)

| Item | Why it matters | Next step |
|---|---|---|
| Rate limiting is per server instance and keyed on the raw token | brute force and scraping are not really throttled | use Vercel Firewall rate limits, or key on the verified user plus real client IP with shared storage |
| Email verification for invitations relies on Supabase "Confirm email" staying on | if switched off, an unverified person could claim an invitation | keep it on; take verification from a server-controlled source |
| Gmail/QuickBooks OAuth state is not single-use and the callback does not re-check permission | a leaked state could attach someone else's mailbox within 10 minutes | store a nonce server-side, delete on use, re-check membership |
| Stripe key checked by prefix only | a restricted key with write scopes would be accepted | verify the key's permissions |
| Tenancy values are transaction-local; a mid-request commit would drop them | latent (no live path today) | re-apply on each transaction start |
| `pip-audit` in CI never fails the build | vulnerable dependencies would not block | remove `|| true` after clearing current findings |
| Fonts not preloaded; fonts/CSS import all weights | small first-load cost | latin-only imports, preload the main font |
| Dashboard makes three serial API calls before content | slower first paint of data | prefetch in parallel once a session exists |
| Sending domain not verified (paid) | invitation emails land in Spam | buy a domain, verify it in Brevo |
| Keyboard and screen-reader testing, 200% zoom | needs a person with assistive technology | schedule a manual pass |
| Landing-page copy and header/hero | another session is mid-change | review after that work lands |
